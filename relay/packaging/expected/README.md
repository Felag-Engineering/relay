# Expected package contents: the Relay

This directory is the reviewed baseline that `scripts/package-guard.sh content` checks the
Relay's release packages (`relay`, `.deb` and `.rpm`) against. The guard reads each package with
`dpkg-deb` or `rpm`, never with nfpm. It is told the release version and architecture, and
computes the package's identity from them. It never takes the identity from the package. The
relay-daemon's baseline is [`daemon/packaging/expected`](../../../daemon/packaging/expected/README.md),
checked the same way.

What it checks, and nothing more:

- **Identity.**
  - On .deb, the whole control file (`dpkg-deb -f`) must equal `relay.deb.control`. Only three
    fields are filled in: `Version` (`<base>[~<pre>][+<meta>]-1`, no epoch), `Architecture`
    (`amd64` or `arm64`) and `Installed-Size`, which is read from the package and must be a
    number. Every other field must match exactly, the package name and the `Maintainer`
    included.
  - On .rpm, `NAME EPOCHNUM VERSION-RELEASE ARCH` must equal `relay`, `0`, the same version, and
    `x86_64` or `aarch64`.
- **Payload listing.** It must equal `relay.<deb|rpm>.files`, one entry per line: mode string
  (which gives the type), owner, path. On rpm each entry also has `caps=`, where `(none)` means
  no file capability. No entry may be setuid, setgid or sticky, and no rpm entry may carry a
  capability. Nothing is under `/etc` or `/var`: `relay.toml` is generated by the maintainer
  scripts on a first install, never package-owned.
- **Maintainer scripts and triggers.** The scripts are [`../scripts`](../scripts).
  - On .deb, the control archive must hold exactly `control`, `md5sums` and the four scripts.
    Each script must be byte-equal to its source.
  - On .rpm, `rpm -qp --scripts --triggers --filetriggers` must equal the source scripts. The
    only allowance is the header line and trailing newline rpm prints around each scriptlet.
- **Relationships.** They must equal `relay.<deb|rpm>.relations`. The package depends on nothing:
  the rpm requires only the `rpmlib()` capabilities rpm itself adds. The expected version-release
  is written as `@VR@`, and the expected rpm architecture tag as `@ISA@`.
- **Files carried from the repository.** These must be byte-equal to their sources:
  - the unit, `relay.sysusers.conf`, `relay.toml.in` and `relay.toml.example`;
  - `configuration-guide.txt`, in both of the places it is installed;
  - `LICENSE`.

The guard does not check the bytes of the binary; the release compares those with the release
binary in its own step. It also does not check file timestamps, or the deb `md5sums` member
beyond its presence.

Change a file here only in the same change that changes the manifest at `../nfpm/relay.yaml`.
A diff to this directory is a diff to what lands on every Relay host, and it is reviewed as one.
