# Relay threat model

**Status:** kept current. Last audited against the fourteen invariants and the ADR amendment
chain on 2026-10-02; every invariant amendment must update this page in the same PR (`AGENTS.md`,
*Amending one is not finished until its consumers are updated*).

Relay is remote code execution as a service, driven autonomously by an AI-agent across a
fleet of Nodes. This document frames the adversaries and trust boundaries it must hold against
before it runs on real machines.

## Product bet and kill criterion

Relay bets that large fleets will let an AI-agent operate them autonomously only if the
control plane is built for **structural distrust**: every layer assumes the layer above it
may be compromised, jailbroken or simply wrong, and enforces its own limits regardless. That is
why Operations are typed rather than shell strings, why Policy is enforced locally on the Node
and only ever queried (never set) by the Relay, and why a blast-radius cap sits between any
single decision and the whole fleet. Distrust is the enabling condition for the autonomy the
product bets on, not a compliance layer added afterward.

The bet has a falsification condition:

> Relay exists for autonomous AI operation of large fleets under structural distrust. If
> customers at that scale are content with prompt-level guardrails over SSH, Relay has no
> market.

The trust boundaries below are where the architecture asserts distrust; the adversary
catalogue is who that distrust defends against.

## Trust boundaries

The request path for any action is AI-agent → Relay → relay-daemon → Node OS, with a
separate, out-of-band path for Policy (operator → Node) and a certless bootstrap path for a
new Node's identity (relay-daemon → CA). At each boundary, one side must not be able to compel
the other beyond what the architecture allows.

| Boundary | Untrusted side | Trusted side | What crosses | Primary control at the boundary |
| --- | --- | --- | --- | --- |
| AI-agent ↔ Relay | AI-agent (authenticates as a machine Account) | Relay | MCP tool calls / Control API requests | Relay-side authorization (deny-by-default) plus Selectors → Policy → blast cap; the Control API can never reach Relay configuration of either tier ([ADR-0010](../adr/0010-control-api-and-account-model.md) as amended 2026-09-15, invariant #11). |
| Relay ↔ relay-daemon | The network, and any peer that fails cert verification | Relay and relay-daemon mutually, once mTLS-verified | Tasks, results, PolicySnapshots, Facts | mTLS everywhere; the daemon refuses an untrusted Relay; Node identity is its client cert ([ADR-0005](../adr/0005-grpc-bidi-over-mtls-transport.md), [ADR-0006](../adr/0006-node-enrollment-identity-and-label-authority.md), invariant #6). mTLS authenticates the transport but does not make an authenticated Relay authoritative over the daemon — the Node still distrusts the Relay's intent by design (see row 4 and the Malicious Relay adversary below). |
| relay-daemon ↔ Node OS | The incoming Task | The local Policy engine | Three tiers: Native Operations by argv (never `/bin/sh`); Template Operations by a structure fixed in a root-owned local file with slot values passed as positional parameters and never part of the parsed text, a slot standing only as a word of a top-level command, and `path` values free of whitespace and shell metacharacters (ADR-0021 amended 2026-10-14 and 2026-10-15; **R29**); Raw Exec argv-only and regex-gated | Nothing on the wire can compose or escalate a command (invariant #1, [ADR-0021](../adr/0021-local-template-tier-shipped-read-catalog-native-freeze.md)); deny-by-default Policy ([ADR-0001](../adr/0001-structured-operations-with-regex-gated-raw-exec.md), [ADR-0002](../adr/0002-node-side-policy-is-locally-rooted-and-remotely-immutable.md), invariants #1, #3). |
| Operator ↔ Policy file | Anything over the wire | The local Policy file/owner | Nothing writable — the Relay may only *query* Policy (fingerprint/snapshot) | Policy is locally-rooted and remotely-immutable; the Relay only reads it, never writes it ([ADR-0002](../adr/0002-node-side-policy-is-locally-rooted-and-remotely-immutable.md), invariant #2). |

The scope is gated to entries rendering as exactly one Selector term — refused at mint and again when a stored scope is used to enroll (#555). Designed, not built: a mint form that asks how many Nodes, and the join string shown apart from the command that consumes it ([ADR-0048](../adr/0048-joining-is-one-command.md)), and the remaining first-party installation artifacts ([ADR-0033](../adr/0033-first-party-installation-artifacts.md); milestone v0.6.5). |

## Adversary catalogue

### Compromised Node

**Assumed capabilities:** Full control of one Node and its relay-daemon process. Can forge
its own `node:` labels, lie in the Facts it self-reports, and — by lying in `Hello` — influence
the Relay-derived `state:` labels. Can lie about the risk class of its own Template Operations,
which can only loosen a Template dispatch's cap and approval match when every Node the dispatch
reaches lies the same way (R28). Can never write `relay:` or `tag:` (invariant #7, four
namespaces).

**Goal:** Escalate to other Nodes, or forge trust it does not have (e.g. attract Selectors or
Operations meant for a different Node or trust domain).

**Primary defense:** The daemon enforces Policy locally and deny-by-default regardless of
what the Relay asks for, and a compromised Node can never forge `relay:` labels — the
security lane it would need to attract into or evade is Relay-set and Node-immutable
([ADR-0002](../adr/0002-node-side-policy-is-locally-rooted-and-remotely-immutable.md),
[ADR-0006](../adr/0006-node-enrollment-identity-and-label-authority.md), invariants #3, #7).

**Recorded disposition (v0.0.8):** the forgeability of `node:` labels is **accepted for
launch** by [ADR-0017](../adr/0017-node-origin-label-trust.md). Forge-to-attract and
forge-to-evade are blocked in the security lane (it targets `relay:`) and residual only in the
routine lane, which is trusted as much as the Node by design. The `relay:` namespace is
structurally un-forgeable, but the security lane's *use* of it is convention today; **#243**
tracks making that structural when the security-lane actions are built.

### Stolen API credential

**Assumed capabilities:** A valid API Token, usable at its Account's role.

**Goal:** Run unauthorized Operations, or widen the blast radius beyond what the Account
should be able to reach.

**Primary defense:** The Control API manages runtime objects only. It writes no Relay
configuration of either tier: the security floor is a file the Relay cannot write, and the
reach-bounding settings (blast caps, approval-gate rules) are host files today and, where they
become runtime objects, Console-only. A bearer credential therefore cannot raise its own blast
cap or remove a gate, and every request still passes Selector → Policy → blast cap regardless
of the credential's role ([ADR-0010](../adr/0010-control-api-and-account-model.md) as amended
2026-09-15, invariant #11).

**The only out-of-band approval lever**
([ADR-0044](../adr/0044-the-console-does-not-decide-approvals.md)): a human Account's API Token can decide a parked approval it is eligible for, on the Control API
decision endpoint, with no step-up at the moment of deciding. Since `approval.md` AP-80 removed
the Console's approval surface, that endpoint is the only out-of-band decision path. Bounded by
the audience, requester exclusion, role floor and plan-hash binding on each decision, and by the
blast cap and Node Policy underneath.

### Hijacked Console session

**Assumed capabilities:** An authenticated browser session belonging to a human Account —
obtained by session theft, stored XSS in the Console, or a CSRF-forged request from another
origin.

**Goal:** Elevate by administering Accounts and tokens, or redirect routine work by retagging
Nodes. The Console runs no command on any Node
([ADR-0052](../adr/0052-the-console-watches.md)), so this adversary cannot dispatch from it.

**Primary defense:** The Console is internal-only, never internet-facing (ADR-0009); it has no
dispatch route, and the structural `no_dispatch` guard covers it like every adapter; the
capability layer's role gate decides `operator`/`admin`, not the Console; privilege-granting acts
require **step-up re-authentication**. CSP and CSRF discipline are load-bearing controls here, not
hygiene; see **R11**.

**Tags** ([ADR-0050](../adr/0050-tags-are-the-operators-labels.md)): a hijacked `operator` session
can rewrite tags, which moves Nodes into or out of routine Selectors. It cannot move a dispatch out
of a gate (gate rules match no label), reach the security lane (`relay:` only), or widen what any
Node's Policy allows; every change is audited with old and new values.

**Reach-bounding settings** live in the Relay's configuration file in the MVP, so no session can
change a blast cap or a gate rule. If they move to the store (`roadmap: relay/settings-in-the-console`),
**R15** returns.

**Step-up is a window for Account acts** (owner decision, 2026-10-05, #879): for the four
privilege-granting Account acts, step-up is a recent-authentication window (default 5 minutes,
at most 15, set only in the root-owned file), so a hijacked session inside the window after the
human's own step-up can perform them without the password. Bounded by the window, the
per-session stamp, session rotation on every step-up, and CSRF and CSP.

**Console passwords** ([ADR-0045](../adr/0045-console-passwords-temporary-at-creation-and-self-service-change.md),
designed, not built): a hijacked `admin` session with step-up (or inside the window) can create a
human Account and read its temporary password from the response — a new Console identity, which
is the reach it already has by creating an `admin` machine Account and minting it an API Token,
bounded the same way (step-up, `admin`, a row on Access per act). It cannot change its victim's
password: the current password is proved on every change and the window never satisfies it. A
human who changes their password ends every other session of their Account, which evicts a
hijacker. A temporary password in transit is live for up to 72 hours, and reaches only a
restricted session that can set the Account's password.

**No approval lever:** the Console decides no approvals
([ADR-0044](../adr/0044-the-console-does-not-decide-approvals.md), `approval.md` AP-80), so this
adversary cannot decide any approval, singly or in bulk (**R22**, closed). Out-of-band decisions
sit behind the **Stolen API credential** boundary.

### Jailbroken AI-agent

**Assumed capabilities:** Full, adversarial control of the orchestrator driving the Relay.

**Goal:** Coerce the fleet into actions outside its intended bounds.

**Primary defense:** The AI-agent is just an Account and gets nothing other AI-agents can't
have. Every call meets Selector → Policy → blast cap and the gate; it cannot write a tag
([ADR-0050](../adr/0050-tags-are-the-operators-labels.md)), and Relay keeps no fleet model it
could rewrite for the next session ([ADR-0051](../adr/0051-the-fleet-model-is-split.md),
invariant #9).

**Approvals on a token session** ([ADR-0047](../adr/0047-approval-is-one-in-band-answer.md),
amended 2026-10-23): an elicited answer on an API-token session counts as that session's Account.
A jailbroken AI-agent that can read its own session's API token, from its client's configuration
on the same machine, can call Relay directly and answer its own approval questions, recorded as
the token's Account. Bounded by the blast cap, each Node's Policy and the audit trail, which
records the decision as a token-session answer; **R45** records the residual.

**Gleipnir's Plans** are carried out by the harness, one tool call at a time, and Relay holds no
route of its own ([ADR-0049](../adr/0049-plans-belong-to-the-harness.md)). A jailbroken AI-agent
in a compromised harness can therefore reorder, skip or substitute the steps of a Plan a person
approved, and Relay will not notice: each step is its own dispatch, meeting the gate, the blast cap
and each Node's Policy alone. That ceiling is what bounds it, and **R14** records the residual.

### Malicious Relay

**Assumed capabilities:** A compromised or hostile central Relay.

**Goal:** Push forbidden actions to Nodes, or mutate a Node's Policy to weaken its defenses.

**Primary defense:** Policy is locally-rooted and remotely-immutable — the Relay may only
*query* it, never write it over the wire — and the daemon enforces deny-by-default whatever the
Relay sends. mTLS is mutual: the daemon verifies the Relay's cert and refuses an untrusted
Relay, and the Node's own identity is its client cert, so a Node cannot be tricked into obeying
an imposter Relay
([ADR-0002](../adr/0002-node-side-policy-is-locally-rooted-and-remotely-immutable.md),
[ADR-0005](../adr/0005-grpc-bidi-over-mtls-transport.md)/[ADR-0006](../adr/0006-node-enrollment-identity-and-label-authority.md),
invariants #2, #6).

### Network attacker

**Assumed capabilities:** Full network position — can intercept, inject, or replay traffic.

**Goal:** Impersonate the Relay or a Node, or inject Tasks that were never issued.

**Primary defense:** mTLS everywhere; the daemon refuses an untrusted Relay and Node identity
is its client cert; at-most-once Task dedup blunts replay of a captured Task
([ADR-0005](../adr/0005-grpc-bidi-over-mtls-transport.md),
[ADR-0006](../adr/0006-node-enrollment-identity-and-label-authority.md),
[ADR-0004](../adr/0004-async-job-execution-model.md), invariants #6, #4).

### Findings

**Finding 1 — unmapped invariant:** invariant #8 (`/proto` single source of truth) maps to no
runtime trust boundary. It is a build-time contract-integrity invariant enforced by CI gates
(`proto-check`, `proto-breaking`): it underpins what crosses Relay ↔ relay-daemon rather than
acting at it. Not a defect; disclosed so "every invariant maps to a boundary" has an honest,
recorded exception. Invariant #13's risk-class-contract half shares this build-time property.

**Finding 2 — boundary coverage:** all five trust boundaries are defended by at least one
invariant — there is no undefended boundary. AI-agent ↔ Relay: #5, #9, #10, #11, #13; Relay ↔
relay-daemon: #2, #4, #6, #7, #12, #13, #14; relay-daemon ↔ Node OS: #1, #3, #12; Operator ↔
Policy file: #2; Enrollment (certless) ↔ CA: #7.

**Observation (not a finding):** the Trust boundaries table names AI-agent ↔ Relay by the
AI-agent surface; the Control API and Admin Console are additional crossings of the same
caller ↔ Relay boundary, all gated by the one capability layer (invariant #10). The Console runs
no command ([ADR-0052](../adr/0052-the-console-watches.md)): it cancels, administers Accounts,
tokens, tags and Policy aliases, and decides no approvals

## Acceptance (v0.0.8 sign-off)

The milestone's four acceptance criteria, with evidence and status. Sign-off is a **human
decision** (this milestone is human-led).

1. **Threat-model doc + every invariant mapped to a boundary — MET.** This document: Trust
   boundaries, Adversary catalogue, and the 14-row invariant→boundary map, with Finding 1
   recording invariant #8 as a disclosed build-time exception.
2. **Raw Exec red-team regression suite, no surviving bypass — MET (unconditionally, as of
   v0.0.9).** The suite exists (`daemon/crates/relay-policy/src/raw_exec_redteam.rs`, rows R1–R18 +
   the Axis 7 canonicalization rows + the `file.read` path-argument table; re-pins in
   `daemon/src/raw_exec.rs`). The two bypasses held open at v0.0.8 sign-off, #236 and #227,
   are fixed by [ADR-0018](../adr/0018-canonical-path-matching-for-file-read.md) (#247) and
   [ADR-0019](../adr/0019-canonical-argv-matching-for-raw-exec-deny.md) (#248); their tests
   pin the fixes and **no `#[ignore]`d bypass remains**.
3. **Bounded fuzzers in CI, zero known crashes — MET.** Go native fuzz (6 targets incl.
   `FuzzSignCSR` on the certless CSR path) run bounded nightly (`.github/workflows/security-nightly.yml`
   fuzz job; `make fuzz-relay`); Rust `proptest` suites over policy and dispatch
   (`daemon/crates/relay-policy/src/proptests.rs`, `daemon/crates/relay-policy/src/decide_tests.rs`, `daemon/src/dispatch.rs`) under `cargo test`. No crash reproducers
   committed. Coverage-guided `cargo-fuzz` runs nightly (`fuzz-daemon`) over the daemon's prost
   decode surface, the Raw Exec gate's argv round-trip (ADR-0019) and the canonical-path
   precondition (ADR-0018) through `Policy::decide` (`daemon/fuzz/`, `make fuzz-daemon`).
4. **Daemon runs a documented least-privilege profile — applied + documented; live
   verification OUTSTANDING.** The shipped unit carries `SystemCallFilter=@system-service`,
   `SystemCallArchitectures=native`, `MemoryDenyWriteExecute=yes`, `CapabilityBoundingSet=CAP_DAC_READ_SEARCH`,
   and `TasksMax=4096` (`daemon/packaging/relay-daemon.service`); the posture is documented in
   `docs/operations/daemon-privilege-posture.md` (offline `systemd-analyze` exposure 3.7→2.1).
   The profile has **not been exercised on a live systemd host** (the dev fleet is Docker);
   verifying all five Operations plus a permitted Raw Exec under the filter **requires a human
   on real hardware** and is the one outstanding acceptance task. #224 applied the profile
   (PR #241) and closed; the live run is tracked by #246.

**Sign-off status: pending human decision.** The disposition of #227 and #236 is discharged
(both fixed before shipping binaries). The live least-privilege verification (#246) remains
outstanding; every other criterion is met.

Acceptance status rather than letting the doc drift.
