## Questions for the owner

Each has a recommended default. The plan is written on the defaults, and each one names the step
it changes.

1. **DI-35 cannot be placed.** It needs a rendered enrollment bundle, and nothing renders one:
   the `render` option ADR-0032 puts on the mint is `enrollment.md`'s, and that spec is
   aspirational and defers it to Future work. The claim also carries its own open question
   (which artifact it pins once there are four daemon packages). **Default: retag DI-35 to
   v0.7.0**, where the Console renders bundles (ADR-0030), and decide the pin then. Alternative:
   pull ADR-0032 rendering into v0.6.5 as a new step after S4, pinning one digest per package
   format and architecture from the *previous* release. A same-release pin cannot work: the
   Relay binary is built before the packages it would pin.
2. **Nothing issues a join string.** DI-22 and DI-37 read one, but no Relay surface emits one:
   the mint response carries only the token. **Default: S4 adds `join_string` to the
   `POST /api/v1/enrollment-tokens` response**, which `enrollment.md` already describes
   (aspirational, so it binds nothing). The address is the certificate hostname plus the
   node-plane listener's port, so no new setting is needed. Without this step, an operator would
   have to build the string by hand.
3. **The join string is a `/proto` message.** It is a Relay→daemon contract, so it lives where
   invariant 8 puts every such contract, and buf's breaking-change gate covers it from then on.
   **Default: S1 adds a `JoinString` message** (address, CA SHA-256, Enrollment Token, format
   version). The encoded form is `glp_join_` followed by unpadded base64url of the serialized
   message. Alternative: a hand-written text format with shared test vectors in both languages
   (rejected below).
4. **Where the join string lives, and how the unit stays quiet.** **Default: in the daemon's
   environment file as `RELAY_JOIN`.** On a Node with neither an identity nor a join string,
   the daemon logs one line and exits 0. `Restart=on-failure` does not restart a clean exit, so
   the unit ends inactive and never failed. With this default, R16, R36, DI-27's file and
   DI-31's purge stay accurate as written, and the default Policy already denies that file.
   Your example, systemd OR-conditions, needs the join string in a file of its own
   (`ConditionPathExists=|…/node_id`, `|…/join`). It is possible, but it costs four things:
   - purge would not remove a file the package did not create, so R36's compensating control
     breaks;
   - the default Policy needs another deny;
   - `RELAY_JOIN` placed in the environment file would leave the unit unstartable, because
     conditions also block a manual start;
   - R16 and R36 would need rewording.

   Changes S6, S7, S12.
5. **DI-10 conflicts with ADR-0031 decision 4.** DI-10 says the persisted identity stores no
   address. ADR-0031 says the daemon persists the address and `RELAY_ADDR` overrides it. Under
   *When documents and the code disagree*, the spec is the presumed defect, and a human
   resolves it. **Default: S6 keeps DI-10 true.** The address comes from `RELAY_ADDR` if set,
   otherwise from the join string. Nothing is persisted. ADR-0031 decision 4 stays unbuilt, and
   you reconcile it with `enrollment.md`. One consequence: config management that clears the
   join string (R16's control) must keep `RELAY_ADDR` set.
6. **Is RC-21's list of bind-time settings complete?** It names listen addresses, the CA
   directory, the store path and the certificate hostname. Turning the control plane or the
   Console on or off, or changing the OAuth provider, rebuilds a listener or a surface.
   **Default: treat those as bind-time as well, so a reload refuses with "restart required".**
   That needs a one-line RC-21 edit before S10. Alternative: make them live, roughly doubling
   S10.
7. **DI-23 and audit flooding.** A revoked daemon redials every few seconds, forever. **Default:
   the first refused dial per Node is recorded at once, then at most one record per Node per
   hour, carrying the count of refusals suppressed in between.** The claim says a dial attempt
   "is recorded". If every attempt must have its own record, say so; that turns a revoked fleet
   into an unbounded audit writer on a single store connection.
8. **DI-3's manual syscall check.** DI-3 says no package carrying the unit ships until the
   enroll→connect→execute trace has been run on a real systemd host. **Default: S15 adds that
   trace as a CI job on the runner VM itself, against the packaged unit, and a human signs off
   its first green output in the S15 PR** before S13's packages are attached to any release.
9. **How `relay init` runs.** **Default: it runs as the Relay's account (`sudo -u relay relay
   init`).** It loads `relay.toml` through the same check as the server, so root is refused by
   RC-15's "runs as uid 0" rule and no root-owned file ever lands in the state directory. It
   refuses when the store does not exist yet ("start the Relay first"), so the Relay stays the
   only thing that creates the CA and the store. It asks for the first Console password at a
   prompt with no echo, and never prints it.

## Intent

Today a Relay host is configured by `RELAY_*` environment variables and flags that systemd hands
it. A Node is configured by a hand-couriered CA bundle and a token. Neither has a package. This
milestone does four things:

- The Relay reads one root-set TOML file, and refuses to run if it could write that file or
  anyone else could read it (gap row 11 closes).
- A Node joins with one pasted value, which pins the Relay's CA.
- Both binaries ship as reproducible `.deb`/`.rpm` packages, proven on every supported platform
  by CI.
- `relay init` replaces the two bootstrap verbs.

## Shape

### Seams that do not move

- **`newServer(Config)` / `newServerWithHooks`** stays the composition root's one entry point.
  The new loader *produces* a `Config`; every e2e test that builds a `Config` literal keeps
  working.
- **The capability layer's interfaces.** Reach settings get a provider the layer consults (see
  *Reload*). No adapter gains a setter, and no route or tool writes configuration (RC-11, RC-32).
- **`Enrollment.Enroll`** and every Node-plane RPC are unchanged. The join string only changes
  what the daemon trusts *before* it sends the token.
- **The daemon's Policy and Template loaders**, and their mode refusals (DI-12, DI-20), are
  unchanged. Packages decide what is *placed*, never what the daemon *does* (ADR-0033 decision 4).
- **The release's binary build**: two passes, a byte comparison, static guards, cosign keyless.
  Packaging is added downstream of it and never rebuilds a binary.

### Key designs

**The join string (S1, S4, S6).**
- **What the daemon pins:** the SHA-256 over the CA certificate's DER, which is the number
  `relay init` and the Console already show (`ca.Fingerprint`).
- **What the Relay must present:** the CA certificate in its TLS chain. Today it presents the
  leaf only, which is why S4 exists.
- **What the daemon sends before verification:** nothing. The token goes out only after the pin
  matches (`enrollment.md` refusal).
- **What a later start uses:** `ca_bundle.pem` in the state directory, which DI-22 says the
  daemon writes. The join string is inert from then on.

**The unit guard (S6, S12).**
- The unit still has `Restart=on-failure`.
- With neither an identity nor `RELAY_JOIN`, the daemon exits 0 with one log line naming both
  settings. The unit ends inactive, never failed and never retried.
- At the next boot, or when `relay-daemon join` or config management starts it, the daemon finds
  the join string and enrolls.
- No path unit and no timer exist, so nothing watches for the join string (DI-25).

**The configuration file (S8, S9).**
- **Sections:** `[node_plane]`, `[control_plane]`, `[console]`, `[ca]`, `[store]`, `[tls]`,
  `[oauth]`, `[approval]` and `[log]`, plus `[reach]` and `[enrollment]` for RC-22's values.
  Exact keys are decided in S8's PR, against the example `relay.toml` that the drift test pins
  to `Config`.
- **Settings with no claim of their own:** dispatch concurrency and the webhook timeout are
  plain values in the file too.
- **Secrets:** a secret key `x` may be given as `x = "…"` or `x_file = "/path"`. Giving both is a
  refusal. The approval webhook URL is a secret for every purpose RC-18 names.
- **Startup order:**
  1. Refuse retired `RELAY_*` names (RC-13).
  2. Open and check the file (RC-15, RC-16).
  3. Decode strictly (RC-12).
  4. Validate (RC-19, RC-20).
  5. Open and check every named file.
  6. Check the state locations (RC-17).
  7. Only then `newServer`.
- **What RC-17 checks:** the CA directory, the CA key and the store's directory each meet the
  generated-material rule. Co-locating them is the package's layout (RC-25), not something the
  check enforces.

**Reload (S10).**
- On SIGHUP the Relay runs steps 2–6 of the startup order again, then diffs the result against
  the running snapshot.
- A changed bind-time setting refuses the whole reload. So do any check failure and any invalid
  value. In each case the running snapshot is untouched and the process stays up. Go's default
  SIGHUP action is termination, so the handler is what makes "never exits" true.
- On success it swaps one atomic snapshot and the approval gate, and changes the log level and
  format through a swappable handler.
- It records one host-attributed audit record (the principal the Freeze signal lever uses),
  listing the changed keys. Changed secret keys are listed by name only.

**Packages (S13, S14).**

| | relay-daemon | relay-read (catalog) | relay |
|---|---|---|---|
| Binary | `/usr/bin/relay-daemon`, root `0755` | — | `/usr/bin/relay` |
| Unit | `/usr/lib/systemd/system/relay-daemon.service` | — | `/usr/lib/systemd/system/relay.service` |
| Owned content | reference default Policy under `/usr/share/relay-daemon/` | Templates under `/etc/relay-daemon/templates.d/relay-read/`, plain package files (not `config`/`noreplace`) | `sysusers.d` entry; guide under `/usr/share/doc/relay/` |
| Placed once, if absent | live Policy (DI-26), environment file `0600` root (DI-27) | — | `relay.toml`, generated, `root:relay 0640` (RC-25) |
| Created dirs | `/etc/relay-daemon`, the Policy directory (empty), `/var/lib/relay-daemon` `0700` | — | `/etc/relay` root `0755`; `/var/lib/relay` `relay:relay 0700` |
| Depends | — | relay-daemon | — |

- **One rule for all three packages:** on a first install only, and only if `/run/systemd/system`
  exists, run `systemctl preset`. That enables on Debian and Ubuntu. On RPM-family hosts it
  follows the presets, which leave an unlisted unit disabled. Nothing ever runs `start` or
  `restart`.
  - Upgrades run `daemon-reload` only. Config management restarts the unit (DI upgrades
    section).
  - Remove stops and disables the unit before deleting the binary.
- **What the package created:** a preinst records which fixed paths already existed, as
  booleans in a package-written marker. Purge reads only that marker, and only ever acts on
  literal paths, never on a path read from an operator-edited file (DI-31, RC-26).
- **What counts as a first install:** on `.deb`, preinst `install` with no old version. On
  `.rpm`, `$1 == 1`; there the two absence checks are the whole guard (DI-26).
- **Relay purge:** moves `/var/lib/relay` to a timestamped sibling, re-owned `root:root` and
  `0700` throughout, and prints where it went. It never deletes the Relay's account.
- **Missing FQDN:** if postinst cannot determine the host's fully qualified name, it writes
  `relay.toml` with the hostname key commented out. The Relay then refuses, naming the setting
  (RC-19), and the guide says so. It never writes a placeholder value.

**Catalog name binding (S2).**
- **The ledger:** a committed file beside the catalog, listing every Template name ever
  released, with a digest of its canonical body and risk class. The digest is computed by the
  daemon's own Template parser, not by text comparison.
- **Three checks:**
  - A daemon test fails if any catalog name's digest differs from its ledger entry.
  - A script fails if the ledger changes anything other than appending entries, or marking an
    entry withdrawn, compared with the most recent release tag's ledger.
  - The release workflow refuses a catalog name missing from the ledger.
- A withdrawn name stays in the ledger, so it can never come back with a different body.

## Constraints

- **Invariant 11 / ADR-0043.** The Relay reads its floor itself and checks the property directly.
  Nothing it runs can write the file: `/etc/relay` and `relay.toml` are root's; the unit has no
  capabilities; and the check refuses a writable file anyway, so the property holds even off the
  packaged layout. Secrets never touch the environment or argv: RC-13 refuses even their names.
  `relay init` reads the file and writes none of it. Reload re-applies the check before anything
  else.
- **Invariant 8.** The join string is a `/proto` message (S1), first in the sequence, with both
  sides generated.
- **Invariant 6 / ADR-0005, 0006, 0031.** The daemon still refuses an untrusted Relay. The pin
  moves the trust anchor's integrity into the string. `Enroll` stays the one certless RPC, and
  the shared certificate's `ClientAuth` is untouched.
- **Invariant 2.** No package step, and not `join`, writes a live Policy after first placement.
  `join` writes only the environment file. The Relay delivers nothing to a Node.
- **Invariant 14 / ADR-0014.** Packages are release attachments the customer's tooling installs.
  The Relay pushes nothing, and the daemon still never upgrades itself.
- **Invariant 1.** Maintainer scripts and the unit are host packaging, not Operations. The catalog
  ledger is what stops an upgrade from changing what an allowed Template name runs (ADR-0021 as
  amended).
- **Invariant 10.** Configuration has no adapter writer. The reach-settings provider is consulted
  by the capability layer, and no surface can reach it to write.
- **ADR-0030.** The binary loses two verbs and gains one. `init` performs only acts no
  credential could yet perform, and its recovery path is an explicit flag.
- **ADR-0033 (all amendments).** No `curl | sh`, no hosted repository, no package signature,
  enable-but-never-start, first-install-only placement, purge semantics, one unit per binary
  at `/usr/bin`.
- **ADR-0022 as amended.** The exact-path denies are added. The drop-in-under-another-name residual
  is unchanged and still has no threat-model row (DI open question).

## Rejected

- **`dpkg-deb` + `rpmbuild` directly.** `rpmbuild` strips and post-processes binaries by
  default, and we need byte-for-byte; two native toolchains on one runner.
- **fpm.** Ruby runtime in the release path, and weaker reproducibility controls than nfpm.
- **Conffile / `%config(noreplace)` for the Policy or `relay.toml`.** Withdrawn by ADR-0033: an
  unedited conffile is replaced on upgrade.
- **A hand-written join string format.** Two parsers kept in step by test vectors alone; `/proto`
  already exists for exactly this.
- **Pinning the server leaf or SPKI.** The leaf rotates every fourteen days, and ADR-0031 chose
  CA DER for legibility.
- **A path unit watching for the join string.** DI-25 forbids it.
- **Restarting on package upgrade.** "Never starts the daemon"; config management restarts.
- **`BurntSushi/toml`.** Workable, but it reports unknown keys after decoding rather than refusing
  them during it, and its errors embed source text we would have to strip.
- **Comparing the catalog against the previous release tag only.** A name withdrawn in one
  release and re-added in the next would slip through; the ledger keeps every name.
- **Keeping `RELAY_*` for one release.** ADR-0043 decision 6.
- **Per-consumer reload hooks without a provider.** A dozen ad-hoc reload paths in
  security-surface packages; one snapshot behind one seam is what RC-29 needs anyway.

## Risks

- **nfpm's `.rpm` reproducibility.** Build time and header ordering have to honour
  `SOURCE_DATE_EPOCH`. The double build catches a failure, but a failure blocks S13. If nfpm
  cannot produce a reproducible `.rpm`, that is a stop-and-escalate, not a reason to drop the
  comparison.
- **systemd in containers.** It is not the real sandbox. Namespacing directives can behave
  differently nested, so the matrix proves package behaviour and the S15 VM trace proves the
  unit. Neither substitutes for the other.
- **Scale of the composition-root change.** S9a deletes about 30 flags that dozens of tests, the
  dev fleet and the demo touch. Keeping `newServer(Config)` fixed is what bounds it.
- **Linux-only facts.** `hostfile` needs ACL xattrs, `fstatfs` and capabilities. On other
  operating systems it must refuse to start, so a developer running the Relay on macOS loses
  that. Tests that call `newServer` directly are unaffected.
- **Release time.** Sixteen matrix jobs gate every release.
- **Ubuntu 26.04 and RHEL 10 images.** Both must exist as systemd-capable images on both
  architectures; UBI 10 init is the RHEL row. A missing image means that platform is not
  supported (DI-33), which is not something S15 should work around.

## Open

- **Exact TOML keys and section names.** Decided in S8's PR against the example file. Forced by
  S8.
- **The Policy directory's path.** S13 creates it empty, and DI-36 (v0.7.0) gives it meaning.
  `/etc/relay-daemon/policy.d` is proposed; it must agree with `policy.md` before S13.
- **The webhook URL as a `_file` secret.** It is redacted either way; whether file form is
  offered is decided in S8.
- **Approval gate content on reload.** S10 re-reads and applies it, since RC-15 re-checks the file
  anyway. AP-4 still reads "loaded at startup", which stays true but incomplete; flag it to the
  owner in S10's PR.
- **`RELAY_FREEZE_RELEASE_REASON`.** It is an operator note read when SIGUSR2 arrives, not a
  setting, so it stays off RC-13's list. S9a confirms it is the only remaining environment read
  outside dev builds.
- **Standalone Relay unit and example `relay.toml` under `SHA256SUMS`.** ADR-0033 lists them, but
  only DI-32 claims the daemon's. S14 attaches them; a claim for them is the owner's to add.
- **The first Console password.** Prompted (default) or generated and printed once. Decided in
  S11.
