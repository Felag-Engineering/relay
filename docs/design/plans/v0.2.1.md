# v0.2.1 — Node connection: self-report change audits, replacement audit, clock skew, Hello without a Node ID

**Spec:** `docs/specs/node-connection.md` — claims NC-33, NC-34, NC-35, NC-36, NC-37, NC-38, NC-39
**Milestone:** v0.2.1   **Opened:** 2026-11-06

## Intent

The Relay starts writing down what changes about a Node between its connects: a new Policy
or Raw Exec state, a new or older daemon version, or a new client certificate, each as an
audit record with before and after values (NC-33..NC-35). It also records stream
replacement, the trace a shared or stolen certificate leaves (NC-36, R54). Every kind of
record is limited per Node, so neither a Node that keeps changing its report nor two parties
sharing one certificate can grow the trail without bound (NC-36, NC-39). The Relay measures
each Node's clock skew from its heartbeats (NC-37), and `Hello` stops carrying a Node ID the
Relay never trusted (NC-38). None of this ever refuses a connection or a dispatch.

## Shape

**What changes**

- **`/proto`** (S1). `Hello.node_id` gets `[deprecated = true]` and a comment saying it is
  never set or read. The field is kept, because buf's FILE breaking rules forbid deleting it.
  The `Hello.labels` comment changes to "node-space only; any other namespace is dropped
  (invariant 7)". Both sides are regenerated: Go with `make proto`, Rust in `relay-proto`'s
  `build.rs`.
- **relay-daemon.** `run_tunnel` builds `Hello` in a small pure function (the same shape as
  `policy_snapshot`) that never sets `node_id`.
- **`registry`** (S2). `Report` gains no field, so none of the following can travel in a
  self-report.
  - `Node.ReportedRawExec` has three states: not reported, disabled, enabled. It holds the
    last reported value. Only the new `RecordPolicySnapshot(nodeID, rawExecEnabled)` writes
    it, and `Upsert` never touches it, so a stream that ends before its snapshot leaves the
    previous value in place.
  - `Node.FirstConnectedAt` is a Relay-authored marker. `MarkConnected(nodeID, at)` sets it
    once, after the tunnel's first successful `Upsert`. Enrollment never writes it, and
    nothing a Node reports does.
  - `Node.ClockSkew` and `Node.ClockSkewMeasuredAt` (zero means not measured), with a
    `ClockSkewKnown()` helper on the model of `CertProvenanceKnown`.
  - `RecordHeartbeat(nodeID, at, skew)` writes `last_seen` and the skew in one statement and
    replaces `UpdateLastSeen`.
  - One SQLite migration adds five nullable `nodes` columns. It backfills
    `first_connected_at` from `last_seen` where `daemon_version` or `policy_fingerprint` is
    non-empty: only the tunnel's `Upsert` writes those, so either one proves an earlier
    connect.
  - `eventsink.registryObserver` passes the new methods through without publishing them,
    for the same heartbeat-rate reason as today.
- **`audit`** (S3). Four kinds, each listed in `allKinds`, `notAnAuthFailureKinds` and the
  Console's `activityNonCallKinds`:
  - `node_policy_changed`
  - `node_daemon_version_changed`
  - `node_cert_changed`
  - `node_stream_replaced`

  In all four, `NodeID` is the subject, `Principal` and `Attribution` are empty (no Account
  acted, the `KindProtocolViolation` reasoning), and `Reason` is `key=value` text. A value that
  was not reported renders as `none`:
  - Policy: `policy_fingerprint_before= policy_fingerprint_after= raw_exec_before= raw_exec_after= changes=<n>`,
    where each Raw Exec value is `true`, `false` or `unknown`.
  - Version: `version_before= version_after= downgrade=true|false|unknown changes=<n>`. The
    marker is `unknown` when either side does not parse as semver.
  - Certificate: `cert_fingerprint_before= cert_fingerprint_after= changes=<n>`.
  - Replacement: `replacements=<n>`.
  - `n` counts the events since the previous record of that kind, including this one. Before
    and after are the values of the change that wrote the record; a change the throttle
    suppresses adds only to the count.
  - Every value is already bounded: Hello's ingress bounds (NC-21), the read-back bounds
    (NC-22), and Relay-computed certificate fingerprints.
- **`auditsink.ConnectionRecorder`** (S3). Modelled on `RevokedDialRecorder`.
  - **One throttle, shared by all four kinds** and keyed by Node and kind. Its window is a
    `10 * time.Minute` constant. The first event is recorded at once. After that there is at
    most one record per window, written on the first event at or after the window.
  - **State is in memory** (owner decision): a restart may add one record per Node per kind.
    There is no timer and no goroutine. An entry whose window has passed with nothing pending
    is deleted during a sweep that runs at most once per window, on a call, so the map does
    not grow with the fleet.
  - **Writes are synchronous**, bounded by a fixed budget, and fail-open: a failed write logs
    one warning and returns no error. The window stays closed after a failure, and the count
    carries into the next record.
- **Tunnel server** (S4a–S6). It calls the recorder through an interface declared in
  `cmd/relay` with exported method names (the pattern of `transport.RevokedDialObserver`),
  nil-guarded like `reg`, `policy` and `vocab`. The comparison is a pure function next to the
  tunnel. At connect the server:
  - Reads the stored record with `Get` before the `Upsert` and keeps it as the stream's
    baseline.
  - After a successful `Upsert` and before the Ping, calls `MarkConnected` and writes the
    version and certificate records. Ping stays the tests' sync point.
  - Treats the connect as a first connect, for NC-33 and NC-34, when the baseline has no
    `FirstConnectedAt`.
  - Compares the certificate (NC-35) whenever the baseline's `CertFingerprint` is non-empty.
    Enrollment stores it, so even a first connect compares.
  - Resolves the Policy record once per stream, when the first message after `Hello` arrives:
    - If that message is a `PolicySnapshot`, the server calls `RecordPolicySnapshot` and
      writes the record when the fingerprint differs, or when both Raw Exec states are known
      and differ.
    - If it is any other message, or the stream ends first, the server writes the record only
      when the fingerprint differs, with `raw_exec_after=unknown`.
  - Counts a replacement in its own per-Node bookkeeping: `streamClaims.open` reports whether
    another stream for the Node was live. The tunnel then calls the recorder outside
    `streamClaims.mu`, so the count works with execution on or off.
  - Computes skew on each heartbeat as `unix_millis` minus the Relay's receive time, so a
    positive value means the Node is ahead. Network delay is included. A timestamp of zero or
    less, or one whose difference does not fit a `time.Duration`, is recorded as not measured.

**Fixed seams:**
- The capability layer, `capability.AuditSink`, and the `audit.Repository` and `audit.Record`
  shapes.
- `Router.Register` and `WithOnDisplaced`. With execution on, the displaced stream still ends
  through them.
- The `registry.Report` type, `Upsert`'s signature, and enrollment.
- Every read surface (Open 1).
- The Task path.
- The heartbeat, keepalive and backoff constants.

## Tests

Every test that proves a claim carries `// Proves NC-n.` (`/// Proves NC-n.` in Rust) directly
above the function, so `make spec-proof` picks it up. Two harnesses are used:

- **`tunnel_test`'s bufconn.** No TLS, so no peer certificate. It uses an in-memory registry
  and a capturing recorder.
- **`startRelay`.** Its bufconn runs real mTLS against the real store.

## Constraints

- **Invariant 6 and ADR-0006.** Identity comes only from the verified certificate. NC-38 deletes
  the last place the Relay looked at a Node ID sent on the wire. ADR-0006 already says the
  stored fingerprint follows the next `Hello`, so a renewal shows up as one NC-35 record.
- **Invariant 7.** No label path changes. The `Hello.labels` comment fix makes `/proto` agree
  with the code, which accepts only `node:`.
- **Invariant 8.** S1 edits `/proto` first and regenerates both sides, with no hand edits. The
  change is additive: deprecated, not deleted (ADR-0014).
- **Invariant 9.** Clock skew and `FirstConnectedAt` are Relay-authored fields, apart from the
  report. `Report` cannot carry them, and S2's guard limits who writes them. `ReportedRawExec`
  sits beside the Policy fingerprint, never inside Facts.
- **Invariant 10.** The capability layer does not change. These records are the Relay's own
  observations of the Node plane, written through `auditsink` just as protocol violations and
  revoked dials are. They are not acts through a surface, and no adapter gains a path to a
  Node.
- **Invariant 11.** The 10-minute window, the write budget and the sweep cadence are
  constants. No setting is added.
- **Invariants 12 and 2, ADR-0002.** The Relay records the Raw Exec flag the daemon reports. It
  never evaluates it, and it never sets it.
- **Invariant 14 and ADR-0014.** A version record never refuses anything. The minimum-version
  gate does not change.
- **ADR-0017.** The records are evidence of what a Node *reported*, not of its state: a lying
  Node can forge its version, fingerprint or Raw Exec flag. It cannot fake a first connect,
  because the marker is Relay-written and set once.
- **ADR-0046.** Claims are promoted word for word. R54 is rewritten to say what is true now.
- **Residuals (state them in the PRs).**
  - *Throttle state is in memory.* A restart may add one record per Node per kind, and a count
    still pending at shutdown is lost.
  - *`Get` followed by `Upsert` is not atomic.* Two simultaneous handshakes may each count one
    change, but the throttle bounds it.
  - *Backfill gap.* A pre-v0.2.1 Node with neither a version nor a fingerprint stored is
    treated as first on its next connect, at most once.

## Rejected

- **One kind with a `family=` key.** "Which Nodes downgraded or re-keyed" should be a kind
  filter. The audit filter has no `Reason` filter.
- **A separate downgrade kind.** It is one event in one family, and the marker lives on the row.
- **Before and after in `audit.Record.Args`.** `Args` means Operation arguments, and a reader
  of the trail would take them as arguments.
- **Inferring first connect from absent self-reported values.** NC-22 lets a Node store none,
  so every later connect would look like a first one, and it would suppress NC-35 as well.
- **`Upsert` returning the prior record.** That changes the contract for enrollment and every
  other caller. The tunnel's `Get` is enough.
- **Holding the `Hello` upsert until the `PolicySnapshot` arrives.** The handshake would then
  depend on a second message.
- **`Upsert` resetting `ReportedRawExec`.** A stream that ended early would erase the baseline
  for the next connect.
- **Taking the Raw Exec baseline from the in-memory `policyview` cache.** After a restart, the
  moment every Node reconnects, every record's before value would be blank.
- **Keeping skew in memory.** NC-37 puts it on the registry record, and an in-memory side map
  would be a second home that read surfaces have to join. The migration is needed anyway for
  the marker and the Raw Exec state.
- **Counting replacements at `Router.Register`'s displaced callback.** With execution off there
  is no Router, so nothing would be counted. `streamClaims` sees every stream.
- **Asynchronous writes, or a flush timer for pending counts.** The precedent is a synchronous,
  budgeted, fail-open write with no timer.
- **Peer addresses in replacement records.** No claim asks for them, and the revoked-dial
  precedent never records remote addresses.
- **A skew threshold, refusal or `state:` marker.** NC-37 never blocks.
- **Measuring skew from a round trip.** That needs a `/proto` echo, and the claim names the
  heartbeat's timestamp.
- **Deleting or reserving `Hello.node_id`.** buf's FILE breaking rules forbid it.

## Open

1. **How clock skew reads.** That needs a `query.md` spec edit (`describe_node`, the Control
   API, the Console). S2 leaves the stored value ready. The same edit decides whether
   `ReportedRawExec` or `FirstConnectedAt` is ever shown.
2. **Glossary.** No new term is proposed: "clock skew" is plain English, and NC-37 defines it.
   `GLOSSARY.md` is human-owned.
3. **The stored Raw Exec value can be older than the current connect.** `ReportedRawExec`
   keeps the last value reported, so after a stream that ended before its snapshot, it lags
   that connect. NC-25 says each connect replaces the self-reported fields. Nothing reads the
   value today. If `query.md` ever shows it, the owner decides whether to label it "as last
   reported" or to reword NC-25.

The flapping-pair growth raised in the first draft is resolved by NC-39.
