Problem. The only way to send a Task is a send-func trapped in Open's local scope, reachable through a sink that is nil in production; "which Nodes are connected" is split across three trackers, and the blast-cap has no seam at all.

Solution. One module owns live streams (send-func + connected-set + teardown); the capability layer is the only package that can construct a dispatch — the structural guarantee ROADMAP v0.0.5 mandates.

  • Leverage: one interface, four surfaces (MCP, API, Console, CLI)
  • Locality: offline-fail-fast answerable in one place
  • Blast-cap gets its seam before Jobs land
  • Delete duplicated dispatcher/harnessSink pair
  • Composition root wires one constructor, not 12 flat fields
ADR-0009/0010: building the capability layer on top of the test sink would compromise "only the capability layer constructs a dispatch" from birth. Build this seam first.

Problem. Revocation and Enrollment Tokens are volatile while everything around them persists — RevokeNode never calls SetRevoked, boot never calls RevokedNodeIDs, and no tokens table exists.

Solution. Make the store the single authority for both concepts; the in-memory Denylist becomes a derived adapter rehydrated at boot.

  • Correctness: revocation survives restart
  • Locality: revoke lifecycle readable in one module
  • Registry doc's rehydration promise becomes true
  • Token-revocation barrier stops evaporating
Security finding, not just architecture: today a revoked Node can reconnect after a Relay restart (ADR-0006 strain). Worth fixing ahead of any refactor.

3 · Operation vocabulary as one lookup (daemon)

Strong in-process

daemon/src/operations/mod.rs · daemon/src/dispatch.rs:293-306,375-423 · proto/gleipnir/v1/gleipnir.proto:141-146

Before — one new Operation = 5 edit sites

proto vocabulary table (comment-form)
operations/mod.rs — constant + descriptor + risk_class
operations/new_op.rs — handler
dispatch.rs match #1 — arg-shape (catch-all: _ ⇒ vec![])
dispatch.rs match #2 — handler (catch-all: _ ⇒ "unknown operation")

The two red arms must stay shape-consistent by hand — Policy can evaluate a different arg vector than the handler acts on.

After — one registration

operations::vocabulary

name → (handler, arg-shape, risk_class)

dispatch match arms — absorbed

risk_class() — absorbed

descriptors() — absorbed

dispatch.rs asks the vocabulary; forgetting a registration is impossible, not a runtime "unknown operation".

Problem. The name→handler and name→arg-shape bindings are two hand-rolled matches in dispatch.rs with uncheckable catch-alls, on the security path where Policy and executor must see the same arg vector.

Solution. One lookup owned by operations/mod.rs binds name → (handler, arg-shape, risk class); dispatch stops carrying parallel per-Operation arms.

  • Locality: Policy-arg-vector and handler agree by construction
  • Leverage: new Operation = one registration, not 5 edits
  • Template Operations tier (v1.1.0) registers instead of adding match arms
  • dispatch↔lint "unknown name" contract becomes explicit

6 · One primitive for the honest-cancel race

Worth exploring in-process

daemon/src/executor.rs:203-211 (recv_cancel) · daemon/src/scheduler.rs:159-176 (queued_cancel, self-described mirror) · daemon/src/cancel.rs:38-84 (the contract both depend on)

Before — one rule, three homes

executor::recv_cancel — "send(()) cancels; dropped sender ⇒ pending(), never cancels"
scheduler::queued_cancel — same rule, mirrored select! (doc comment admits it)
CancelRegistry — contract only holds if both mirrors agree

A change to the race rule must be made twice; the compiler never forces agreement.

After

cancel-race primitive

explicit-signal-vs-event select, dropped-sender = pending — once

↑ scheduler queue-wait ↑ executor run-wait

Problem. The safety-critical "honest race" semantic (a Task that won the race reports success, never retroactive cancel — ADR-0013) is implemented in two mirrored select! helpers plus the registry contract they lean on.

Solution. One primitive both the queue-wait and the run-wait consume; the rule gets a single home and a single test suite.

  • Locality: ADR-0013 semantic changes in one place
  • Mirror-drift class of bug eliminated

Smaller findings (no card needed)

  • Blocking I/O on the async runtime — dispatch.rs:379-403 facts/file-read bodies, and executor.rs:116-144 pipe-drain with no timeout (a daemonizing child can stall the mutate lane). Belongs to v0.0.7 hardening.
  • Raw Exec allow-regex sees argv.join(" ") while the executor runs the argv (policy.rs:633-650 vs executor.rs:65-66) — an argv element containing a space changes what the allow-regex sees vs what runs. Deliberate, deny-side element-checked, but deserves an explicit red-team test in v0.0.8.
  • Registry Upsert "who-writes-what" — the field-authority rules live as prose in registry/registry.go but are enforced in store/registry.go; two write-sites (enroll, tunnel) re-derive them. A single documented merge table co-located with the implementation.
  • registry.InMemory (243 lines) — full parallel adapter used only by tests; retire to a test helper or keep deliberately as the second adapter that proves the seam.
  • WithMaxNodes naming trap — it caps registry inserts, not dispatch blast radius; rename before the real blast cap (ADR-0012) lands beside it.
  • parseConfig env-block duplication — six near-identical int-override blocks; will grow one per new cap/limit.
  • policy_check bypasses the owner/group-write gate (documented, offline-lint reason) — the permission gate has exactly one bypass; keep it visible in v0.0.7.
